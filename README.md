# 건강진료센터 셀프 접수 · 관리자 시스템

접수 태블릿, 간호사 PC, 근로학생 PC가 보건실 내부 서버에 접속해 접수와 진료 기록을 함께 관리하는 웹앱입니다. 간호사 PC에서 Node.js 서버를 실행하고 SQLite에 기록을 저장합니다.

**현재 상태:** 서버와 화면 연결 구현 및 로컬 검증 완료. 현장 3대 설치·인증서 설정·동시 사용 검증은 별도 진행해야 합니다. 담당자 인증은 공용 PIN이며 역할별 권한은 아직 분리되지 않았습니다.

## 주요 기능

- 학번·이름·방문 목적을 입력하는 셀프 접수, 세부 증상 복수 선택과 직접 입력
- 두통·감기 선택 시에만 체온 입력 표시. 체온은 선택 항목이며 미입력은 미기록으로 저장
- 서버 저장 성공 후 접수번호 안내, 진행 중 중복 접수 차단
- 방문자 대기 화면에는 접수번호와 상태만 제공
- 담당자 PIN 인증, 기록 수정·진료 시작·완료·취소·당일 복구
- 다른 기기의 변경 알림(SSE)과 주기적 새로고침, 기록 버전 기반 수정 충돌 검사
- 서버 기준 운영시간 검사, 한국 시간 기준 보관 기한 정리
- CSV·클립보드 내보내기, 암호화 백업·복원, 기존 기록 이관
- 개인정보 입력 90초 후 초기화, 담당자 화면 무활동·탭 숨김 잠금

## 실행하기

Node.js **24 이상**과 npm이 필요합니다.

```powershell
git clone https://github.com/heewonjung2/health-center-self-checkin-admin.git
cd health-center-self-checkin-admin
npm ci
npm run serve
```

서버 PC에서 http://127.0.0.1:8080 을 엽니다. 담당자 최초 PIN 설정 후 복구 코드를 별도로 보관하세요. 기본 실행은 로컬 접속 전용입니다.

### 보건실 3대 연결

학교 전산 담당자가 준비한 서버 주소와 TLS 인증서를 사용합니다. 인증서와 개인 키를 모두 지정해야 LAN에 서버를 열 수 있습니다.

```powershell
$env:HC_HOST = '0.0.0.0'
$env:HC_TLS_CERT = 'C:\HealthCenter\certs\server.crt'
$env:HC_TLS_KEY = 'C:\HealthCenter\certs\server.key'
npm run serve
```

세 기기에서 인증서에 등록된 HTTPS 주소로 접속합니다. 태블릿은 주소 끝에 /?kiosk=1을 붙입니다. 방화벽·절전·인증서 신뢰·자동 시작 설정은 [설치 안내](docs/SERVER.md)를 따르세요.

Windows 부팅 시 자동 시작 등록 스크립트도 제공합니다. 인증서 경로를 포함한 명령은 설치 안내에 있습니다.

**Vercel 정적 배포만으로는 이 백엔드가 실행되지 않습니다.** 서버가 꺼지거나 네트워크가 끊기면 접수할 수 없습니다.

## 개발과 검증

```powershell
npm run check
npm run test:watch
npm run build
npm run server
```

프런트엔드 개발은 서버를 실행한 상태에서 별도 터미널의 npm run dev를 사용합니다. /api 요청은 로컬 8080 서버로 전달됩니다. npm run preview는 정적 파일 미리보기이며 서버 실행을 대체하지 않습니다.

최근 로컬 검증: lint, 테스트 **103개**, production build 통과. 실제 Node 서버 상태 응답과 인증서 없는 LAN 공개 차단을 확인했습니다. 테스트 통과는 현장 배포 완료를 의미하지 않습니다.

## 구조

- server/: HTTP/HTTPS API, 서버 PIN 인증, SQLite 트랜잭션, 감사 기록, 보관 기한 정리
- src/components/: 방문자 접수, 담당자 목록·기록 수정, 설정·백업
- src/domain/: 화면과 서버가 공유하는 입력 검증·상태 전환·백업 병합 규칙
- src/lib/api.js 및 src/hooks/useServer.js: 서버 통신과 화면 상태 갱신
- tests/: 도메인·저장·암호화·API·화면 통합 테스트

서버는 Node 기본 모듈을 사용합니다. 화면은 React 19와 Vite 6으로 구성합니다. 새 기록은 브라우저 저장소가 아닌 서버 DB에 저장됩니다.

## 기존 기록과 백업

예전 Vercel 주소와 새 서버 주소는 브라우저 저장 공간이 다릅니다. 예전 앱에서 암호화 백업을 내보낸 뒤 새 서버 설정에서 복원하세요. 새 주소의 ‘이 기기의 기존 기록’ 버튼은 예전 주소의 저장소를 읽지 못합니다.

이관·복원은 기존 기록을 덮어쓰지 않습니다. 동일 ID의 내용이 다르거나 진행 중 접수가 중복되면 작업 전체를 거부합니다. 실행 중 DB 파일을 따로 복사하지 말고 암호화 백업 기능을 사용하세요.

## 운영 범위와 남은 작업

- 간호사·근로학생의 개별 계정과 권한 분리는 미구현입니다. 감사 기록도 공용 담당자 기준입니다.
- DB 파일 자체는 암호화하지 않습니다. 서버 계정·파일 접근 권한과 기관의 기기 보호 설정이 필요합니다.
- PIN과 복구 코드는 해시로 저장하고, 네트워크 전송은 HTTPS로 보호합니다.
- 서버 PC 장애 시 자동 전환이나 오프라인 접수는 지원하지 않습니다.
- 학교 기존 시스템과 API 연동하지 않으며 CSV와 복사 기능으로 전달합니다.
