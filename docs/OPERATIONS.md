# 운영 및 데이터 전환 안내

## 적용 전 체크리스트

1. 운영 기관의 개인정보 처리·보관 기준과 전용 기기 사용 승인을 확인합니다. 이 앱은 인증된 의료정보 시스템이 아닙니다.
2. 실제 방문 기록 대신 가상 데이터로 별도 브라우저 프로필에서 먼저 검증합니다. 미리보기 URL은 운영 URL과 저장소가 달라 운영 기록이 보이지 않는 것이 정상입니다.
3. 운영 기기의 기존 기록을 승인된 위치에 백업합니다. 기존 앱에서는 일자별 CSV를 보관하고, 개발 담당자는 기존 브라우저 저장소 원본도 별도로 보존합니다. 실제 기록을 GitHub·이슈·채팅에 올리지 않습니다.
4. 모든 기존 버전 탭과 창을 닫습니다. 브라우저 데이터 자체는 지우지 않습니다.
5. 검토한 PR을 병합한 뒤 기존 운영 URL에서 새 버전을 엽니다. 담당자가 방문자에게 넘기기 전에 PIN을 설정합니다.
6. 날짜별 건수·학번·체온·처치 내용이 이관되었는지 확인합니다. 기존 체온 미입력 기록은 `미기록`으로 표시합니다.
7. 접수 → 진료 시작 → 기록 수정 → 완료, 오접수 취소·복구, CSV와 암호화 백업을 가상 데이터로 확인합니다.
8. 담당자 확인이 끝난 뒤 운영을 재개합니다. 운영 재개 전 상태가 불확실하면 기존 승인된 접수 절차를 사용합니다.

## 최초 설정과 화면 잠금

- PIN은 **숫자 6~12자리**, 기본 PIN 없음. 기기/브라우저별 최초 설정이 필요합니다.
- 저장되는 것은 랜덤 salt와 PBKDF2-SHA-256(600,000회) 검증값입니다. PIN 원문은 저장하지 않습니다.
- 관리자 화면은 5분 무활동 또는 탭이 숨겨지면 잠깁니다. ‘잠그고 접수 화면으로’ 버튼도 제공합니다.
- 실패 누적 5회부터 60초간 화면 잠금 해제가 제한됩니다. 이는 브라우저 UI 수준의 제한이며 보안 서버의 로그인 제한이 아닙니다.
- 새 PIN은 기기 설정에서 현재 PIN을 확인한 뒤 변경합니다. PIN을 변경하면 다른 탭도 잠기며, 복구 코드는 그대로 유지됩니다.

### 복구 코드

- PIN 최초 설정 직후 **복구 코드**(예: `ABCDE-FGHJK-...`, 20자)가 **한 번만** 표시됩니다. 인쇄하거나 담당자 인수인계 문서에 적어 **기기와 분리된 안전한 곳**에 보관하세요. 화면을 닫으면 다시 표시되지 않습니다.
- 저장되는 것은 복구 코드의 PBKDF2-SHA-256 해시뿐입니다. 원문은 저장하지 않습니다.
- PIN을 잊었을 때: 잠금 화면의 ‘PIN을 잊으셨나요?’ → 복구 코드 입력 → 새 PIN 설정. 재설정하면 **새 복구 코드가 다시 발급**되므로 즉시 보관하세요.
- 복구 코드를 분실했거나 노출이 의심되면 기기 설정 › ‘복구 코드 재발급’에서 현재 PIN 확인 후 새로 발급합니다. 이전 코드는 즉시 무효화됩니다.
- **PIN과 복구 코드를 모두 분실하면** 이 기기의 잠금은 재설정할 수 없습니다. 기관 담당자가 기기 소유·운영 권한과 원본 백업을 확인한 뒤 개발 담당자에게 `hongik-health-admin-lock-v1` 키 초기화를 요청해야 합니다. 브라우저 전체 데이터 삭제로 해결하지 마세요(기록도 함께 사라집니다).
- 복구 코드도 PIN과 같은 **화면 잠금 수준**의 보조 수단입니다. 개발자 도구나 기기 접근을 통제하지 못합니다.

### 키오스크 모드와 담당자 진입

- 방문자 태블릿은 주소 끝에 `?kiosk=1`을 붙여 엽니다(예: `https://.../?kiosk=1`). 이 모드에서는 화면에 ‘담당자 화면’ 버튼과 PIN 설정 배너가 **표시되지 않습니다.**
- 키오스크 모드에서 담당자가 관리자 화면에 들어가려면 상단 **로고(H+)를 2초 안에 5번** 누릅니다. 숨겨진 진입점이며 방문자에게 안내하지 않습니다.
- 최초 PIN 설정은 `?kiosk=1`을 뺀 주소로 열어 진행합니다.
- 담당자 전용 PC(사무실)에서는 `?kiosk=1` 없이 열어 ‘담당자 화면’ 버튼으로 진입합니다.

### 운영 시간

- 기본값은 한국 시간 기준 **평일 09:00–17:30**입니다. 기기 설정 › ‘운영 시간’에서 시작·종료 시각과 요일을 변경할 수 있습니다.
- 운영 시간 밖에는 방문자 화면에 안내 문구가 표시되고 접수가 막힙니다. **담당자 화면은 영향을 받지 않습니다.**
- 종료 시각은 미포함입니다(17:30이면 17:29까지 접수 가능). 자정을 넘기는 운영 시간은 지원하지 않습니다.

## 저장 위치와 버전 전환

| 항목                    | 저장 키                          |
| ----------------------- | -------------------------------- |
| 기존 MVP 배열           | `hongik-health-registrations`    |
| v1.1 schemaVersion 2    | `hongik-health-registrations-v2` |
| 관리자 화면 잠금 검증값 | `hongik-health-admin-lock-v1`    |
| 운영 시간 설정          | `hongik-health-hours-v1`         |

앱은 기존 배열을 검증하고 새 형식으로 저장한 **후에만** 기존 저장 키를 제거합니다. 기존 ID·이름·학번·증상·약품·처치 내용을 유지하며, 당시 없던 체온은 null로 기록합니다. 학번의 앞뒤 공백은 제거하고 영문은 대문자로 통일합니다. 기존 분 단위 시간만 남은 기록의 동일 시각 순서는 기존 배열의 역순으로 보완합니다.

구형 앱은 새 저장 키를 사용하지 않아 새 기록을 덮어쓸 수 없습니다. 그러나 구형 탭에서 계속 접수하면 별개의 기존 키가 재생성됩니다. 두 키가 함께 발견되면 앱은 두 원본을 보존하고 변경을 차단합니다. 모든 구형 탭을 닫고 개발 담당자가 **두 원본을 각각 안전하게 백업하고 차이를 확인**해야 합니다. 어느 한쪽을 무조건 삭제하거나 단순히 병합하면 안 됩니다.

**구형 버전으로 단순 배포 롤백하지 마세요.** 구형 앱에서는 새 기록이 보이지 않습니다. 코드 롤백과 데이터 복구는 별개입니다. schemaVersion 2를 이해하는 직전 안정 버전으로 복구하거나, 검증된 변환 도구를 준비한 뒤 전환해야 합니다.

## 보관 기한

- 기존 경계 규칙을 유지합니다. 한국 시간으로 오늘이 8월 28일이면 7월 29일 이후 기록을 보관하고 그 이전 날짜는 제거합니다. 즉 ‘오늘 + 이전 30일’의 날짜 범위입니다.
- 시작 시와 실행 중 1분마다 확인합니다. 앱이 닫혀 있을 때에는 정리 작업이 실행되지 않습니다.
- 취소는 논리적 상태 변경이며 즉시 개인정보 삭제가 아닙니다. 취소 기록도 같은 보관 기한을 따릅니다.
- 백업 파일·CSV·클립보드는 앱의 자동 삭제 대상이 아닙니다. 기관 기준에 맞춰 따로 정리해야 합니다.
- 미래 날짜 기록이나 손상된 기록은 오래된 데이터로 간주해 지우지 않고 오류로 차단합니다. 기기 날짜부터 확인합니다.

## 백업과 복원

- 기기 설정에서 12~128자 암호를 두 번 입력하고 암호화 백업을 내려받습니다. 관리자 PIN과 다른 암호를 사용하고 별도로 보관하세요.
- 백업은 PBKDF2-SHA-256 + AES-256-GCM, 매번 새 salt·IV를 사용합니다. 암호를 잊으면 복호화할 수 없습니다.
- 복원은 10MB 이하의 `.health-backup.json` 파일을 선택하고 암호를 입력해 미리 확인한 뒤 실행합니다.
- 유효한 보관 기간의 새 ID만 추가합니다. 기존 ID의 내용이 다르면 전체 복원을 중단합니다. 기존 기록을 자동 덮어쓰기 하지 않습니다.
- 진행 중 접수 중복은 복원을 차단합니다. 같은 날짜 접수번호가 겹치면 새 번호를 부여하므로 복원 후 번호를 확인하세요.
- 손상된 저장소에서는 일반 복원을 차단합니다. 먼저 암호화 원본 백업을 확보하고 개발 담당자가 손상 원인을 확인해야 합니다. ‘빈 목록으로 초기화’하는 자동 복구는 하지 않습니다.

## CSV와 복사

- 선택 날짜·상태·검색 조건에 표시된 목록만 CSV로 내보냅니다. 파일명에도 선택 날짜와 상태가 반영됩니다.
- UTF-8 BOM, CRLF 줄바꿈, 따옴표 escaping을 적용합니다. 수식 시작 문자와 앞쪽 공백/제어문자·전각 문자를 감지해 작은따옴표를 붙입니다.
- CSV 보호는 모든 스프레드시트 프로그램이나 재저장·재열기에서 보장되지 않습니다. 외부에서 재편집한 파일의 수식을 활성화하지 말고 필요하면 열을 텍스트로 가져오세요. 정확한 복원에는 CSV 대신 암호화 백업을 사용하세요.
- CSV는 **평문 개인정보 파일**입니다. 다운로드 확인 절차는 보호 장치가 아니라 안내입니다.
- 전체 복사는 학번, 이름, 체온, 증상, 투약, 처치 순서의 탭 구분 텍스트입니다. 기존 학교 시스템 양식과 맞는지 담당자가 확인해야 합니다.

## 장애 대응

| 증상                           | 대응                                                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 저장 실패                      | 입력 내용이 유지됩니다. 저장 공간·브라우저 설정을 확인하고 다시 시도하세요. 성공 안내 전에는 접수 완료로 간주하지 않습니다. |
| 다른 화면에서 수정됨           | 편집창을 닫고 최신 기록을 다시 연 뒤 수정합니다.                                                                            |

| 구형/신형 기록 동시 발견       | 기존 탭을 모두 닫고 두 원본을 개별 백업한 뒤 충돌을 확인합니다.                                                             |

| HTTPS/Web Locks 오류           | 최신 Chrome 또는 Edge와 HTTPS 주소를 사용합니다. 로컬 개발은 localhost를 사용할 수 있습니다.                                |

## 실제 운영 전 추가 검증

자동화 테스트는 실제 기기·브라우저·Excel의 동작을 전부 대체하지 않습니다. 담당자와 태블릿 터치 입력, 360/768/1280px 화면, 대화상자 키보드 이동, 백그라운드 잠금, 두 탭 동시 작업, 실제 Excel 가져오기, Vercel 보안 헤더 적용을 확인하세요. 모든 검증에는 가상 데이터만 사용합니다.
