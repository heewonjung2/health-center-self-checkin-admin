# 보건실 운영 절차

## 최초 설치

[SERVER.md](SERVER.md)를 따라 간호사 PC에서 로컬 실행과 최초 PIN 설정을 완료합니다.
복구 코드를 별도로 보관하고, HTTPS 인증서와 방화벽을 설정한 뒤 근로학생 PC와 태블릿을 연결합니다.
실제 기록을 넣기 전에 가상 정보로 접수·동기화·수정 충돌·취소·백업 복원을 확인합니다.

## 매일 시작

서버 PC의 절전 해제와 서버 실행을 확인합니다. 세 기기의 대기 현황이 일치하는지 확인합니다.
접수 태블릿은 키오스크 주소를 열고 담당자 세션을 잠급니다.
운영시간은 서버 설정에서 관리하며 접수 API도 같은 설정을 검사합니다.

## 서버 연결 실패

접수를 다시 제출하기 전에 담당자가 서버 기록에서 저장 여부를 확인합니다. 응답이 끊겼더라도 서버에는 저장되었을 수 있습니다.
서버 전원·네트워크·인증서·방화벽을 확인합니다. 브라우저 기록 삭제나 DB 초기화로 해결하지 않습니다.
복구 전에는 기관의 대체 접수 절차를 사용합니다. 자동 오프라인 동기화는 지원하지 않습니다.

## 기존 기록 이전

예전 앱 주소에서 암호화 백업을 내보내고 새 서버에서 복원합니다. 출처가 다른 브라우저 저장소는 새 서버에서 직접 읽을 수 없습니다.
충돌 시 파일 원본을 보존하고 담당자가 내용을 비교합니다. 다른 ID의 진행 중 중복도 자동 덮어쓰지 않습니다.

## 백업·복구

설정의 암호화 백업을 정기적으로 내려받고 암호를 분리 보관합니다. 별도 시험 환경에서 복원을 확인합니다.
실행 중 SQLite 파일과 WAL을 각각 복사하지 않습니다. 파일 단위 백업은 서버 정상 종료 뒤 진행합니다.
보관 기한 정리는 서버 시작 시와 실행 중 매시간 수행하며 서버가 꺼져 있는 동안에는 수행되지 않습니다.

## 롤백

변경 전 백업을 확보하고 서버를 종료한 뒤 이전 버전으로 전환합니다. 서버 도입 이전 버전은 SQLite 기록을 직접 읽지 못합니다.
코드만 되돌리고 기록 이관이 끝났다고 판단하지 마세요. 백업의 읽기·복원 호환성을 시험 환경에서 확인해야 합니다.
