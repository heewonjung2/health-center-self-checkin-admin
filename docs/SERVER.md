# 보건실 서버 설치·운영

간호사 PC에서 서버를 실행하고 근로학생 PC와 접수 태블릿이 같은 서버에 접속합니다.
기록은 서버의 `data/health-center.sqlite`에 저장됩니다. 서버가 꺼지면 접수를 중단합니다.

## 로컬 확인

Node 24 이상 설치 후 프로젝트 폴더에서 다음을 실행합니다.

```powershell
npm ci
npm run serve
```

기본 주소는 `http://127.0.0.1:8080`입니다. 기본 설정은 서버 PC 안에서만 접속할 수 있습니다.
담당자 최초 설정에서 PIN과 복구 코드를 준비하고 가상 정보로 접수 → 진료 시작 → 수정 → 완료/취소 흐름을 확인합니다.

## 실제 3대 연결

학교 전산 담당자에게 서버 고정 주소와 그 주소에 맞는 TLS 인증서를 준비하도록 요청합니다.
세 기기 모두 인증서를 신뢰해야 하며 인증서 경고를 무시하고 운영하지 않습니다.
서버 인증서와 개인 키 파일을 지정하면 HTTPS 서버로 실행됩니다.

```powershell
$env:HC_HOST = '0.0.0.0'
$env:HC_TLS_CERT = 'C:\HealthCenter\certs\server.crt'
$env:HC_TLS_KEY = 'C:\HealthCenter\certs\server.key'
npm run serve
```

브라우저에서 `https://서버의인증서에등록된주소:8080` 으로 접속합니다.
태블릿은 주소 끝에 `/?kiosk=1`을 붙입니다. 개인 키는 서버 계정만 읽도록 관리하고 Git에 올리지 않습니다.

**인증서 없이 `0.0.0.0` 등 LAN 전체에 HTTP로 노출하는 설정은 서버가 시작 단계에서 거부합니다.**
기본 실행은 `127.0.0.1` 로컬 전용이며, LAN 운영은 TLS 설정이 있어야 합니다.

서버 PC의 절전을 해제하고 방화벽은 학교 전산 정책에 따라 승인된 내부 네트워크/기기에만 해당 포트를 허용합니다.

## 자동 시작

로컬 전용 자동 시작:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -LocalOnly
```

LAN HTTPS 자동 시작:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -CertPath "C:\HealthCenter\certs\server.crt" -KeyPath "C:\HealthCenter\certs\server.key"
```

자동 시작 작업에도 `HC_HOST`, `HC_TLS_CERT`, `HC_TLS_KEY`가 포함되도록 스크립트가 등록합니다.
인증서·개인 키 파일을 옮기면 작업을 다시 등록해야 합니다.

## 데이터 공유와 동기화

- 세 기기는 같은 Node.js 서버와 SQLite DB를 사용합니다.
- 접수 번호는 서버가 한 곳에서 발급합니다.
- 다른 기기의 접수/상태 변경은 SSE로 즉시 알리고, 30초 주기 동기화도 병행합니다.
- 기록 수정은 `version` 기반 낙관적 잠금으로 충돌을 감지합니다.
- 공개 대기 현황 API는 접수번호와 상태만 반환하고 이름·학번·체온은 담당자 인증 뒤에만 조회할 수 있습니다.
- 담당자 PIN/복구 코드는 서버에서 검증하고 세션은 5분 무활동 시 만료됩니다.
- HTTPS 운영 시 세션 쿠키에는 `Secure`, `HttpOnly`, `SameSite=Strict` 속성을 적용합니다.

## 기록 이관과 백업

기존 Vercel 주소와 새 서버 주소는 브라우저 저장 공간이 다릅니다.
따라서 새 주소에서 예전 Vercel의 `localStorage`를 직접 읽을 수 없습니다.

기존 데이터가 필요한 경우 기존 앱에서 암호화 백업을 내려받고 새 서버의 설정 화면에서 해당 백업을 복원합니다.
백업·복원은 서버에서 암복호화하며 기존 기록과 병합 검증을 거칩니다.

운영 중에는 설정의 암호화 백업을 사용하고 암호는 별도로 보관합니다.
SQLite 파일 단위 백업이 필요하면 서버를 정상 종료한 뒤 `data` 폴더를 복사합니다.
실행 중인 DB/WAL/SHM 파일을 제각각 복사하는 방식은 일관된 백업을 보장하지 않습니다.

## 보관·감사

- 30일이 지난 기록은 서버가 주기적으로 정리합니다.
- 접수, 관리자 잠금 해제, 기록 변경, 설정 변경 등 주요 조작은 감사 기록에 남습니다.
- 현재 담당자 인증은 공용 PIN이므로 간호사와 근로학생을 개별 계정으로 구분하지는 않습니다. 역할별 권한과 감사 주체 분리는 후속 확장 범위입니다.

## 운영 전 확인

실제 개인정보를 넣기 전에 가상 데이터로 다음을 확인합니다.

- 세 기기에서 같은 접수 목록이 보이는지
- 한 기기의 상태 변경이 다른 기기에 반영되는지
- 같은 학번의 진행 중 접수가 중복 차단되는지
- 서버 중단 시 연결 오류가 명확히 표시되는지
- PIN 설정·잠금·복구가 동작하는지
- 암호화 백업과 복원이 동작하는지
- 인증서가 세 기기에서 경고 없이 신뢰되는지
- 서버 PC 재부팅 후 자동 시작과 HTTPS 접속이 유지되는지

Vercel 정적 배포는 이 LAN 서버를 실행하지 않습니다.
민감한 개인정보를 다루는 실제 운영 서버는 인터넷에 공개하지 않고 학교 내부망에서만 사용합니다.
